# Генератор экзаменационных билетов

Скрипт `bilety.py` создаёт N экзаменационных билетов по шаблону Word, подставляет
M случайных вопросов из базы и сохраняет всё в новый `.docx`.

На одной странице размещается **два билета**, а если два не влезают (много или
длинные вопросы) — **один билет на страницу**. Решение принимает Word при
открытии файла: каждый билет лежит в невидимой ячейке высотой в половину
страницы и не может разорваться между страницами. Если содержимое билета
больше половины страницы, ячейка растягивается, и второй билет автоматически
уезжает на следующую страницу.

## Файлы в репозитории

| Файл | Назначение |
| --- | --- |
| `index.html` + `assets/` | веб-версия генератора (для GitHub Pages) |
| `bilety.py` | версия для командной строки |
| `Макет.docx` | шаблон билета с заполнителями |
| `Вопросы.docx` | база вопросов (каждый вопрос — отдельный абзац) |
| `config.ini` | значения, которые подставляются вместо заполнителей |
| `Билеты.docx` | результат работы программы (создаётся заново при каждом запуске) |
| `requirements.txt` | зависимости |

## Веб-версия (без установки, для GitHub Pages)

В корне репозитория лежит готовая страница `index.html` — тот же генератор, но
работающий прямо в браузере. Бэкенд не нужен: `.docx` собирается на стороне
клиента, файлы никуда не отправляются.

Что на странице:

1. **Файлы Word** — шаблон билета и база вопросов. Кнопка «Взять файлы из
   репозитория» подставляет `Макет.docx` и `Вопросы.docx` с этого же сайта.
2. **Данные для шапки** — поля создаются автоматически по заполнителям,
   найденным в шаблоне (`<DISCIP>`, `<DATE>`, `<LECTOR_NAME>`, …). Можно вставить
   содержимое `config.ini` — поля заполнятся из него.
3. **Параметры** — N (билетов), M (вопросов в билете), билетов на странице
   (2 или 1), seed (для воспроизводимой выборки), уникальность наборов.
4. **Результат** — готовый `.docx` скачивается, рядом отчёт и предпросмотр
   вопросов по билетам.

Как опубликовать: Settings → Pages → Source: «Deploy from a branch», ветка
`main`, папка `/ (root)`. Страница откроется по адресу
`https://<логин>.github.io/UIT_BILET/`. Файл `.nojekyll` уже добавлен, чтобы
GitHub не обрабатывал сайт через Jekyll.

Структура веб-версии:

| Файл | Назначение |
| --- | --- |
| `index.html` | разметка страницы |
| `assets/style.css` | оформление |
| `assets/app.js` | логика страницы: файлы, поля, скачивание |
| `assets/bilet-engine.js` | порт `bilety.py` на JavaScript: сборка `.docx` в браузере |
| `assets/jszip.min.js` | распаковка/упаковка `.docx` (JSZip 3.10.2) |

`assets/bilet-engine.js` повторяет логику `bilety.py` один в один, поэтому
файлы, полученные из браузера и из командной строки, совпадают по структуре.

## Установка

```bash
pip install -r requirements.txt     # или: pip install python-docx
```

## Запуск

```bash
python bilety.py
```

Все параметры задаются **в коде**, в блоке «НАСТРОЙКИ» в начале `bilety.py`:

```python
TEMPLATE_FILE = "Макет.docx"        # шаблон билета
QUESTIONS_FILE = "Вопросы.docx"     # база вопросов
CONFIG_FILE = "config.ini"          # значения для заполнителей
OUTPUT_FILE = "Билеты.docx"         # куда сохранить результат

N_TICKETS = 10                      # сколько билетов создать
QUESTIONS_PER_TICKET = 3            # сколько вопросов в каждом билете

MAX_TICKETS_PER_PAGE = 2            # 2 — два билета на страницу, 1 — по одному
RANDOM_SEED = None                  # число — воспроизводимая выборка вопросов
UNIQUE_TICKETS = True               # не повторять наборы вопросов в разных билетах
```

Дополнительно можно настроить вид вопросов внутри билета:

```python
QUESTION_NUMBERING = "{n}. {text}"  # нумерация ("{text}" — без номеров)
QUESTION_ALIGNMENT = "left"         # left / center / both
QUESTION_SPACE_AFTER_TWIPS = 60     # интервал после вопроса (567 twips = 1 см)
QUESTION_HANGING_INDENT_TWIPS = 340 # висячий отступ второй строки (0 — выключить)
```

## Шаблон билета

Шаблон — это Word-файл, в котором билет оформлен **таблицей**. Вместо значений
в тексте стоят заполнители вида `<ИМЯ>`:

| Заполнитель | Что подставляется |
| --- | --- |
| `<NUM>` | номер билета (1, 2, 3 …) — свой у каждого билета |
| `<BILET_TASK>` | список вопросов билета |
| остальные (`<DISCIP>`, `<DATE>`, `<LECTOR_NAME>`, …) | значения из `config.ini` |

Заполнитель может быть любым — важно лишь, чтобы для него было значение в
`config.ini`. Заполнители, для которых значения нет, программа не трогает и
предупреждает об этом в консоли. Если в шаблоне нет `<BILET_TASK>`, программа
сообщит об ошибке: именно в это место вставляются вопросы.

## База вопросов

Word-файл, в котором **каждый вопрос — отдельный абзац**. Нумерация Word
(списки «1., 2., …») не требуется и не переносится: программа сама нумерует
вопросы внутри билета. Пустые абзацы, заголовки (стили «Заголовок…», «Heading…»)
и дубликаты пропускаются.

## Файл конфигурации

Формат — «заполнитель = значение», по строке на значение:

```ini
<DISCIP> = ТАУ
<DATE> = 05 ноября 2026
<LECTOR_NAME> = Сидорова Е.Ю.
```

Подходит и обычный INI-вид (`DISCIP = ТАУ`), и строки с комментариями (`#`, `;`).

## Пример вывода

```
Готово.
  Файл:                  /home/user/UIT_BILET/Билеты.docx
  Билетов:               10
  Вопросов в билете:     3
  Вопросов в базе:       26 (использовано 18)
  Билетов на странице:   до 2 (если не влезают — 1)
  Высота полосы набора:  13958 twips
  Место под 1 билет:     6689 twips (шапка ≈ 3516)
  Оценка высоты билета:  6390 twips
```

## Если на странице оказывается по одному билету

Программа пишет об этом предупреждение. Причины и решения:

1. Слишком много вопросов в билете — уменьшите `QUESTIONS_PER_TICKET`.
2. Длинные вопросы — уменьшите `QUESTION_SPACE_AFTER_TWIPS` (например, до `0`),
   кегль вопросов в шаблоне или `QUESTION_HANGING_INDENT_TWIPS`.
3. Очень крупная «шапка» билета в шаблоне — сократите блок «Утверждаю…».
4. Если рамки таблицы «теряются» в вашем редакторе — оставьте
   `FORCE_TABLE_BORDERS = True` (по умолчанию): рамки будут прописаны напрямую,
   а не браться из стиля таблицы.

Оценка «Оценка высоты билета» в отчёте показывает, сколько места займёт самый
высокий билет; она должна быть меньше строки «Место под 1 билет».

## Как это устроено (кратко)

1. Читаются `config.ini` и вопросы из `Вопросы.docx`.
2. Для каждого билета случайно (без повторов внутри билета) выбираются
   M вопросов; по возможности наборы не повторяются между билетами.
3. Копия таблицы-шаблона заполняется значениями: `<NUM>`, значения из конфига,
   вместо `<BILET_TASK>` вставляются нумерованные вопросы.
4. Геометрия таблицы фиксируется: ширины колонок берутся из `tblGrid` шаблона
   и прописываются в каждую ячейку, таблица переводится в режим
   фиксированной разметки, рамки (если в шаблоне их нет) задаются напрямую.
   Без этого редактор «на лету» пересчитывает ширины: правая колонка сужается,
   дата переносится на две строки, а у объединённой ячейки пропадает рамка.
5. Строка с вопросами растягивается (минимум высоты) так, чтобы билет занимал
   свою половину страницы; `cantSplit` запрещает разрыв строки, `keepNext`
   привязывает строки друг к другу — поэтому билет никогда не рвётся между
   страницами и переезжает целиком.
6. Между билетами ставится абзац-просвет `TICKET_GAP_TWIPS` (иначе Word склеил
   бы соседние таблицы в одну).
7. Результат сохраняется в `OUTPUT_FILE`.
